# 方法：一条片子从头到尾

![从一个念头到一条片子：选题门、任务书、口播稿、分镜单、两道审、出片](../docs/img/workflow.png)

这套做法里，渲染交给机器；要人花心思的是前面几步：题选得对不对、稿子听不听得懂、画面有没有在帮忙。车间做一条片子，大致是下面十一步。每一步只写目标和底线，怎么做交给做的人判断（这是车间自己的「规矩的规矩」，见 `规矩怎么长.md`）。

| # | 这一步 | 交出什么 | 细讲 |
|---|---|---|---|
| 0 | 选题门 | 六问打分，8 分以上才做；写一行发布前的预测 | `选题门.md` |
| 1 | 任务书 | 一份单看就能开工的原料：骨架、场景、原话、反对意见、美的要求 | `任务书和全新设计者.md` |
| 2 | 全新设计者 | 另起几位不看规矩、不看旧片的设计者，各出一份方案；挑、拼，交给作者选 | `任务书和全新设计者.md` |
| 3 | 口播稿 | 像跟朋友一口气讲下来那样整段写，写完再对结构 | `稿子写给耳朵听.md` |
| 4 | 分镜单 | 每场答四问：观众要懂什么、画面比喻或证据、随时间怎么变、为什么要动 | `画面规矩.md` |
| 5 | 切句、两道审 | `script.py` 里每句一个 `C(...)`；听众审、结构审都「过」，结论绑定稿子哈希 | `两道审.md` |
| 6 | 配音、回读 | TTS 逐句配；语音识别回读；多音字和声调拼成一段「抽听」给人听 | `声音.md` |
| 7 | 时间轴 | 每个字几秒念到；字幕按词切行 | `../代码/README.md` |
| 8 | 画面 | `render.js` 每场一个函数，动作挂在词上 | `画面规矩.md`、`../形式库/` |
| 9 | 检查、渲染、混音 | 渲染前机器查字和人；按 10 秒一段渲染；配乐盲听；按响度混 | `检查和出片.md`、`声音.md` |
| 10 | 成片审、出片 | 独立审稿人看手机尺寸的联系表和原尺寸静帧；成片压到能发；封面、简介 | `两道审.md`、`检查和出片.md` |
| 11 | 发布、回流 | 勾「AI 生成内容」；24 小时、3 天、7 天回看效果；反馈记下来 | `检查和出片.md` |

## 三层规矩

车间把规矩分三层，开工、改稿、审片前三层都读一遍：

1. **通用**：所有片子都守（这个文件夹里的几份）。
2. **规格和平台**：发在哪、多长（`../规格/`）。管开头门禁、平台界面区、封面、发布。
3. **系列**：是谁的片子。音色、配乐、画风偏好、分寸。车间里有「追本」（从一个日常现象追到底）、「城市志」（一座城的来历）、「单片」（不属于系列的单独一条）。系列的默认值写在每条片子的 `片子.json`，片子里可以改。

## 最容易忘的几件事

- **模板和复制只为拿流程。** 新片子从模板起步，不复制上一条：复制会把上一条的画面习惯一起带过来。画面和配乐按这篇内容重写。
- **片长跟着内容走。** 不为时长砍例子、连接、证据。重复的节拍、跑题的话照样删。
- **改一个字，重审。** 稿子哈希变了，配音的门禁不放行。
- **预告片和切片默认不做**，点名才做。
- **画面、片尾、简介都不加「AI 生成」的字样**，发布时在平台上勾选「AI 生成内容」。
- **助手不碰 key。** key 放在环境变量里，作者自己设，脚本只读变量、不打印。
