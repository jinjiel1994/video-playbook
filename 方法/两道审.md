# 两道独立审

![两道审：配音前审稿子，成片后审画面和声音](../docs/img/review.png)

归原则 5、6 管（[`../原则.md`](../原则.md)）。当时的事见 [`../案例本/`](../案例本/README.md) F 组。

一条片子过两道审：**配音前审稿子**（分听众审、结构审两轮），**成片后审画面和声音**。审稿人都是另起的一个干净会话，只拿到说明和要审的东西，不看代码、不看历史对话、不改文件。这样才看得出写的人自己看不见的毛病。

审稿人要真的「干净」：在仓库里起的子代理会自动带上仓库的说明和最近几条提交标题。听众审要的是第一次听，稿子审过之前，提交标题里别写主干、比喻和稿子原句；要完全隔开，就在仓库外另起会话。

## 第一道：配音前审稿子

先有 `口播稿.md`，再切句，打出一份带编号、带稿子哈希的审稿单（`python3 script.py sheet`）。两轮都审到「总结论：过」才配音；结论和哈希写进 `审稿.md`，配音命令开跑前会核对。**之后稿子改一个字（包括停顿、语速、拼音标注），哈希就变，要重审。**

### 听众审：只给稿子，不给背景

为什么单独要这一轮：审稿人先拿到结构、比喻、主张，读的是字，会替观众把提纲腔的句子补全，审过了听着照样不连贯（F1）。所以审稿子要模拟对面有一个人在听你说话。

给听众审的说明（只填平台、时长、配音，别的一概不说）：

```
你要扮演一个刷到这条视频的普通人，第一次听它。下面是这条中文竖屏视频的旁白稿子，约【几】分钟，发在抖音、视频号，配音是 AI 合成的男声，一句句念出来，屏幕上有字幕。你不知道这条片子想讲什么、用了什么比喻，也不要去猜作者的结构，就当一句句听下来。不要看任何别的文件，不要修改任何文件。

「|」是句中停顿；引号配音时会被去掉；标了 [不出字幕，这句直接以画面文字出现] 的句子会以大字出现在屏幕上。

请输出（中文）：
1. 逐句表：每句一行，「编号｜过 / 改 / 拦｜我听到这句的第一反应（第一人称、口语，比如『啊？谁？』『嗯，懂了』『这话谁会这么说』）｜哪里听不懂、哪里不像人说话、哪里跟上一句接不上｜建议改法（口语，改动尽量小）」。
   - 拦：听不懂，或者会听成别的意思。
   - 改：听得懂，但拗口、像在念提纲或书面语、跟上一句跳了一步、用了没交代过的词。写着「可选」也算改。
2. 整段听下来：哪几处断了、跳了，哪几处我走神了，哪个词我到最后也没明白，哪句话我能复述给朋友听。
3. 开头：你在抖音上刷到它（按【平台会推给的那群人】的身份答），听完前 5 秒会不会划走？为什么？听到第 30 秒，你知不知道这条跟你有什么关系、它要回答你一个什么问题、看完能拿走什么？开口是在说世界、说别人，还是在数落你？你会把它转给谁？
4. 最后一行只写总结论：「总结论：过」「总结论：改」或「总结论：拦」。

## 稿子
【审稿单全文】
```

规则：

- 标了「改」「拦」的照改；**标了「拗口」「不像说话」的，写着可选也改**（F3）。
- **听过三四轮或者大改之后，换一个没听过的新审稿人**（F2）。
- **开头候选那一轮（写稿前）**，听众的角色按平台会推给的那群人来设（讲大理，就是住在那儿、去过、想去的人）；随手刷到的普通人只查听不听得懂、会不会被冒犯，**不拿他「会不会划走」当准**（A8）。另一面：只找目标人群来听也会偏，还要看这群人有多大（A7）。

### 结构审：给背景，查结构、事实、读法、听不听得清

给结构审的说明要填：片长、平台、配音引擎（会不会认拼音）、称呼约定、这条片子的主张和结构。审稿标准：

- **A 结构**：往下追的片子，每层走四步：现象、本层结论、裂缝的前提（这个结论还靠着什么没说破的前提）、追问。下一层开头要回答上一层的追问。别的结构，每一段都要说出它靠着什么，段和段怎么接要念出来。
- **A1 开头**（推荐流的规格）：第一句是不是「奇」或「有戏」；开口有没有指着观众数落；第一帧是不是真东西；30 秒内有没有先给一半答案、说出看完能拿走什么；钩子问的是不是正文真会回答的。
- **A2 名句**：来自书或名言的，那句话有没有在前 20 秒原样念出来。
- **B 删例子，不删连接**：有没有跳步、逼观众自己补逻辑的地方。
- **B2 节拍**：不设片长上限；要指出的是重复和跑题。
- **C 抽象的论断要念出来**，不能只靠画面。
- **D 说人话**：每句都写「对面那个人听到这句的反应」；书面腔；「不是 A，是 B」超过两处；「它」指代不清；中途换比喻；术语没先交代；一句塞太多；结尾问句是不是观众自己会问的。逐条打勾挡不住整体不说人话。
- **E 听得清**：三声连读、近音、多音字、去掉引号后的歧义。
- **F 事实和分寸**：有没有说过头；读法有没有说成定论；涉及别人的地方是否尊重，不能教人操控。

输出：逐句表（编号｜过 / 改 / 拦｜理由｜建议改法）、结构检查（每段靠的证据或前提是哪句）、最后一行总结论。复审时告诉审稿人改了哪几句（改前、改后、上下文），请它确认上一轮的都解决了、新句子没带来新问题。

## 第二道：成片后审画面和声音

成片出来后跑 `./make.sh qc`，出这些材料交给新的审稿人：

- 手机尺寸（216×384）的联系表，**每张 20 格**，按时间排：每句念到一半和快念完各一格，每个转场过了四分之一、一半、四分之三各一格，画面大动（镜头在移、大块东西进出）的地方加一到三格。**一次只给一张**（F6）。
- 格子索引：「表几 格几」对应哪个时刻、哪句台词。
- 机器查出的小字、字压字、字进界面区的清单；时间上的检查（章节名停多久、画面停住的时段、没停够读完的字）；响度跳变；转场和首尾以外的黑屏和静音；混音后回读认不清的句子；成片体积。
- **四张原尺寸静帧**（第一帧、第 3 秒、片长三成处、六成处），只用来看质感。联系表格子太小，看不出质感。

请它逐项查：

- **A 层次**：字和字、字和画面里的东西有没有叠着；一格是不是只有一个重心；转场的三格里有没有半个人、透出上一场的字。
- **B 清晰**：缩到手机大小，要读的字读不读得出（分清哪些是装饰）。
- **C 时间**：画面停住是有意让一句话落地，还是该在这里长出东西。
- **C2 开头和重复**：第一帧和每章第一帧认不认得出；同一个画面节拍重复三次以上，后面有没有提速。
- **D 声音**：响度跳变是有意还是意外；有没有盖过人声的音效。
- **E 质感**：像不像批量货？随便截一帧，能不能当海报？和抖音上同题材最好的几条放在一起拿不拿得出手？字体、小签、标题是这个题材自己的样子，还是哪条片子都能套的默认样子？

输出问题清单：「表几 格几（时刻）｜哪一类｜问题｜建议」，按严重程度排，最后一行总结论。看不清的格子不要猜，写「建议放大看」。

审稿人列问题，写的人逐条改，重渲、重混、出片，再跑 qc。问题都处理了，或者写明为什么不改，这道审才算过。

审了好几轮才查出来的毛病（金光盖住人影、字幕让开的键对不上、同一个人出现两次、数据画面不是一个世界）记在案例本 C7、C8、C11、D5。
